# doc/

`alphazero_mcts.qmd` — the write-up of the network and the search: encoding,
architecture, training, export, the PUCT formulas, graph search, the root
refinements, the self-play learning loop (self-play driver, trainer, replay
window, symmetries, evaluation matches, cluster sizing, KataGo's auxiliary
heads), a code map, a parameter reference, the measurements, and an
appendix with the complete annotated source of every file involved.

`minmax_nnue_dev_player.html` — the minimax NNUE dev player, current version
(`config/search_study/dev_u9_spsa.cfg` = `dev_final.cfg` + the six gains of the
search campaigns U1–U10 + the coverage of U19–U22, constants tuned by SPSA in U23), self-contained HTML with diagrams and interactive
widgets: the search (iterative deepening, aspiration windows, negamax and its
pruning, the sealed pockets as tempo reserves, move ordering with the
coverage of our group, the continuation history, the killers as a bonus and the intercept, the Yolah
table, lazy SMP), the evaluation cache, lazy accumulators and the correction
history, the NNUE network and its SIMD forward pass, its training
(distillation, quantization-aware training, export), and what campaigns
U1–U10 tried (about 200 variants, the tools used).
Written by hand, not rendered by Quarto.

`alphazero_mcts_player.html` — the MCTS player with the value/policy ResNet,
in the same style: the network and its backends, one simulation (PUCT in
KataGo's form, the utility-stdev factor, first play urgency, backup), the
search graph (one node per position, Q from the node and N from the edge, the
node key, tree reuse), the batching of leaves and of threads, the network
cache, the root refinements (noise, forced playouts, policy target pruning,
LCB) and the measured strength.

`yolah_app.html` — the graphical application of `app/` (SDL3), and a
beginner's tutorial of SDL3 through it: build, architecture and threads, the
SDL callbacks, one frame, vector drawing with `SDL_RenderGeometry`, text with
stb_truetype, immediate-mode widgets, the board, the AI roster and the
analysis engine, the theme and sprite files, effects, the screenshot mode.
Screenshots in `figs/app_*.png` (made with `yolah_app --screenshot`).

`distillation_loop.html` — the distillation loop of `nnue/distill_loop.sh`, in
the same style: the games of the dev player (node limit, openings, the 40-byte
records, the tree nodes, the exact results), the training cache (the tree
nodes on the game's path, `zmask`, the window of rounds), the ResNet's
targets and training, the NNUE's teacher and distillation, the evaluation
matches and the SLURM jobs of a round. Stopped after round 0.

`az_gen_loop.html` — the generations loop of `nnue/az_gen_loop.sh`, which
replaced it for the ResNet: MCTS self-play by the current network (every move
recorded, fast searches flagged, exact results from the solver near the end),
the pool of 200 M positions (old cache, then generations) and the draw of a
training, the targets and the optimisation, the matches, the SLURM jobs, the
commands and files; the results of the distillation loop.

`endgame_ybwc.html` — the exact endgame solver of the puzzle editor's
“Vérifier”, made parallel: why the moves cannot simply be shared out, the
“young brothers wait” split points, the cutoff chain, the master and its
helpers, the transposition table shared without a lock, the target goals, the
key moves proved in parallel, the measurements (root split, Lazy SMP, YBWC,
YBWC + ETC + short searches) and the checks. Generated by `build_ybwc_doc.py`
(its code excerpts are cut from the current sources).

`retrograde.html` — the retrograde analysis of private regions: why regions
(measured on real games), clusters and reserves, the exact value of a cluster
(canonical form up to the 8 symmetries, early exit), the table built backwards
layer by layer on the CPU (`test/solo_retro_main.cpp`) and on the GPU
(`test/solo_retro_gpu.cu`: CUDA kernels, thrust), and their use in the exact
solver, the dev minimax (campaign U29) and the MCTS (`nnue/az_regions_match.sh`).
Generated by `build_retro_doc.py`.

These reuse the CSS and the script framework of `minmax_nnue_dev_player.html`
(code blocks, contents, diagram helpers).

`final_*.{h,cpp}` — the code of the final players and tools, cleaned and
commented line by line in French, each checked against the real code by
`test/final_*_check.sh`: `final_dev` (the minimax dev player), `final_nnue`
(its quantized NNUE), `final_mcts` (the MCTS ResNet player), `final_solver`
(the editor's exact solver, sequential: the simplest to read first) and
`final_ybwc` (the same solver, parallel, with the target goals), `final_retro`
(the private regions and their table) and `final_retro_gpu.cu` (the same table on
the GPU, with an introduction to CUDA).

## Rendering

Needs [Quarto](https://quarto.org) and a LaTeX install (TeX Live with
`scrartcl` and `fvextra`; the figures need `pdflatex`, `tikz`, `standalone` and
`pdftocairo`; the PDF listings need the `DejaVu Sans Mono` font for the
box-drawing and Greek characters in the sources).

```bash
figs/build.sh                  # TikZ sources -> 300 dpi PNGs (skips up-to-date ones)
./make_appendix.py             # sources -> appendix.qmd  (re-run after editing any of them)
quarto render alphazero_mcts.qmd
# -> alphazero_mcts.html (self-contained) and alphazero_mcts.pdf
```

## Files

| file | role |
|------|------|
| `alphazero_mcts.qmd` | the document |
| `learning.qmd` | the "Learning by self-play" chapter, included by the above |
| `solving.qmd` | the "Solving Yolah" chapter (retrograde analysis, exact endgames, solvability) |
| `appendix.qmd` | **generated** — the annotated source appendix, included by the above |
| `make_appendix.py` | generates it: the file list, the orientation notes and the symbol tables live here |
| `styles.css` | HTML-only layout: widens the code column for the appendix, holds prose to a readable measure |
| `figs/*.tex` | the TikZ diagram sources; `figs/preamble.tex` holds the shared styles |
| `figs/*.png` | committed, so the document renders without a LaTeX run |

The appendix is generated rather than pasted so the listings cannot drift from
the code. `make_appendix.py` prints a warning if a listed source has
uncommitted changes, which usually means the rendered output is ahead of what
was committed. Per-symbol prose belongs in `make_appendix.py`; line-by-line
commentary belongs in the sources themselves.
